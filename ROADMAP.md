# Roadmap

## Floor 1.0 — Meaning contract

- [x] Establish purpose and boundaries
- [x] Define initial ontology and relationship lanes
- [x] Freeze initial invariants
- [x] Define receipt and authority semantics
- [x] Separate ecosystem responsibilities
- [ ] Record open design tensions as issues
- [ ] Tag the first normative draft

## Floor 1.1 — Executable contract

- [ ] TypeScript domain types
- [ ] canonical JSON serialization
- [ ] one central hasher
- [ ] schema validation
- [ ] append-only in-memory receipt graph
- [ ] authority lease validation and consumption
- [ ] pipeline admission checks
- [ ] canonical and adversarial fixtures
- [ ] conformance CLI

Exit condition: deterministic fixtures pass without a model, database, network, or UI.

## Floor 1.2 — Adapter boundary

- [ ] versioned import/export envelope
- [ ] extension namespaces
- [ ] compatibility and migration rules
- [ ] TranchNode adapter
- [ ] one contrasting product adapter
- [ ] relationship-preserving round-trip tests

## Floor 2 — Ecosystem use

- [ ] publish a tagged contract
- [ ] downstream conformance declarations
- [ ] Project 0 compatibility matrix
- [ ] cross-project receipt traversal demonstration

## Deferred intentionally

- database selection
- authentication provider
- user interface
- vector store
- autonomous agent runtime
- token or economic system
- universal identity

These become legitimate only when the executable contract demonstrates the need.
