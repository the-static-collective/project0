# L-Branch v0.1 Bounded Resonant Propagation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the smallest offline Project 0 reference specimen proving that one admitted excitation can propagate through multiple deterministic local steps while authority, disclosure, and topology remain bounded by the original declaration.

**Architecture:** Add an experimental `src/l-branch/` module parallel to `src/world-encounter/`. It owns versioned L-Branch types, fail-closed validation, Project0 canonical addressing under a distinct experimental domain, and one pure deterministic propagation evaluator over fixture-local candidates. L-Branch records are experimental addressed records, not additions to the frozen `CanonicalReceipt.receiptType` union.

**Tech Stack:** TypeScript 7, Node.js `node:test` / `node:assert`, existing `canonicalizeDomainValue`, existing Project0 verification commands.

**Spec:** `docs/superpowers/specs/2026-08-19-l-branch-v0.1-bounded-resonant-propagation-design.md`

## Global Constraints

- Protocol identifier is exactly `p0.l-branch/0.1`.
- No tenth universal node kind and no new universal relationship kind.
- Do not add to the frozen `RECEIPT_TYPES` union in `src/reference-kernel/types.ts`.
- Reuse `canonicalizeDomainValue`; do not introduce another serializer or hasher.
- No model calls, embeddings, vector search, network, database, scheduler, queue, UI, or autonomous agent loop.
- `influenceRefs` and `authorityRefs` remain mechanically distinct.
- Authority used by every step must be a subset of authority declared at branch admission.
- Candidate enumeration must fail closed for material unavailable under the declared policy/disclosure context.
- Every execution terminates as `completed`, `damped`, `refused`, `exhausted`, or `inadmissible`.
- No private chain-of-thought or scratchpad data enters addressed records.
- Broad gate: `npm run verify:all`.

- [ ] **Step 3: Implement deterministic frontier evaluation**

In `src/l-branch/evaluate.ts`, implement a pure loop with no external state:

1. Address/validate the declaration.
2. Start branch-local available refs with `excitationRef`.
3. Sort candidates by `candidateRef` for deterministic consideration.
4. At each depth/step, consider only declared candidates not already terminally handled.
5. A candidate is eligible only when all required input/influence/authority/policy conditions are satisfied and its depth/frontier placement is within budget.
6. Missing authority or policy produces a refusal record; it does not mutate declaration authority.
7. Successful candidate refs become branch-local available refs for later steps.
8. Decrement `maxSteps`; enforce `maxFrontierWidth` and `maxDepth`.
9. Stop as `completed` on an eligible `terminal: true` candidate; `exhausted` when additional eligible work exists but the budget forbids it; `damped` when budget remains but no eligible work exists; `refused` only when the branch produces no successful step and at least one declared route is refused; `inadmissible` only before propagation begins.

Do not call a model and do not discover candidates beyond the supplied fixture-local array.

- [ ] **Step 4: Address every step and terminal record**

Use `addressLBranchRecord("step", body)` and `addressLBranchRecord("terminal", body)` so ordering and termination are reconstructible from returned refs.
