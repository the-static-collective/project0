# NAV v0.1 — Crossing Witness Design

Status: approved design boundary; implementation not yet authorized

Date: 2026-08-16

## Purpose

NAV v0.1 gives Project 0 a deterministic way to attest **difference across a declared crossing** without pretending to possess a global map or a God’s-eye view.

The first law is:

> NAV may attest difference; it may not manufacture continuity.

The primitive exists to prevent silent collapse of distinctions such as:

- moved vs changed;
- preserved vs merely similar-looking;
- influence vs authority;
- remembered frame vs present frame;
- continuity vs reconstruction;
- same goal wording vs same goal particularity;
- visible path vs authorized crossing.

NAV v0.1 is deliberately a **difference detector**, not a route planner. It does not answer how to bypass a refusal or how to transform a frame so a refused destination becomes reachable.

## Why Project 0 owns the first specimen

Project 0 exists to preserve shared meaning across movement between people, agents, applications, and time. Floor 1.1 now provides deterministic canonical addressing, bounded authority evaluation, append-only receipt history, stable refusal reason codes, and explicit uncertainty. Those are the minimum cold primitives needed for a model-independent crossing witness.

Full Measure may later render or consume NAV results as world-layer experience. Corpus OS may later use NAV alongside Lawful Reachability. Neither should define the shared crossing semantics first.

## Scope

NAV v0.1 introduces an experimental pure module under `src/nav-crossing/`.

It accepts three explicit inputs:

1. a declared `before` frame;
2. a declared crossing;
3. a declared `after` frame.

It produces one deterministic `NavCrossingReceipt` describing only mechanically observable differences among declared dimensions.

The module is not a database, graph crawler, inference engine, model prompt, UI, search system, or world simulator.

## Non-goals

NAV v0.1 MUST NOT:

- compute the minimum world-change needed to make a refused goal reachable;
- recommend alternate authority, evidence, purpose, decoder, constitution, or world;
- infer hidden before/after state from arbitrary history;
- claim that two frames are globally the same world;
- upgrade influence into authority;
- treat visibility or retrieval as traversal authorization;
- decide semantic identity from string or byte equality alone;
- add a tenth canonical Project 0 node kind;
- add a new canonical relationship kind;
- introduce a second canonicalization or hashing implementation;
- depend on a model, embedding service, vector database, network service, or UI.

The immediately following conceptual slice may explore **minimum necessary world-change** as a separate route-planning problem. It is explicitly outside this design.

## Core data model

The module introduces experimental types only. They do not expand the frozen canonical ontology.

```ts
export type FrameSnapshot = {
  frameRef: string;
  constitutionRef: string | null;
  authorityRefs: string[];
  decoderRef: string | null;
  evidenceRefs: string[];
  participantRef: string | null;
  particularityAnchors: Record<string, string | null>;
};

export type CrossingDeclaration = {
  crossingRef: string;
  kind: "document_open" | "analogy" | "memory_return" | "translation" | "room_crossing" | "other";
  declaredPurpose: string;
  evidenceRefs: string[];
};

export type DifferenceDisposition =
  | "preserved"
  | "changed"
  | "absent_after"
  | "new_after"
  | "indeterminate";

export type DifferenceObservation = {
  dimension: string;
  disposition: DifferenceDisposition;
  beforeRefs: string[];
  afterRefs: string[];
  evidenceRefs: string[];
};

export type CrossingStatus =
  | "no_material_difference_observed"
  | "materially_changed"
  | "indeterminate";

export type NavRecordRef = string;

export type NavCrossingReceipt = {
  beforeSnapshotRef: NavRecordRef;
  crossingDeclarationRef: NavRecordRef;
  afterSnapshotRef: NavRecordRef;
  observations: DifferenceObservation[];
  crossingStatus: CrossingStatus;
};
```

The concrete implementation may refine field names if needed to fit existing Project 0 conventions, but it MUST preserve the semantic distinctions above.

## Frame semantics

A `FrameSnapshot` is not an omniscient world state. It is a bounded declaration of the dimensions relevant to one crossing.

The initial tracked dimensions are:

- **frame** — the declared local frame identity;
- **constitution** — the governing constitution or cut reference, when declared;
- **authority** — authority references currently carried or recognized;
- **decoder** — the interpretation/decoding context explicitly in force;
- **evidence** — evidence references visible to this frame;
- **participant** — the traveler/participant identity, when relevant;
- **particularity anchors** — named anchors used to preserve what a goal, object, motif, or identity specifically meant before traversal.

Every tracked dimension is material to the bounded NAV comparison. NAV does not silently decide that one declared dimension matters less than another.

Absence of a declaration is not equivalent to sameness. Missing or insufficient evidence produces `indeterminate` where the comparison cannot be established mechanically.

## Comparison semantics

The pure operation is conceptually:

```ts
compareCrossing(before, crossing, after): NavCrossingReceipt
```

NAV compares **declared references**, not semantic similarity. Exact reference preservation is evidence that the same declared reference survived the crossing; it is not a claim that two independently similar objects share semantic identity.

For scalar nullable dimensions such as constitution, decoder, and participant:

- same non-null reference -> `preserved`;
- different non-null references -> `changed`;
- non-null before and null after -> `absent_after`;
- null before and non-null after -> `new_after`;
- null on both sides -> `indeterminate`.

For required set dimensions such as authority and evidence, arrays are normalized as sets before comparison:

- equal normalized sets -> `preserved`;
- non-empty before and empty after -> `absent_after`;
- empty before and non-empty after -> `new_after`;
- otherwise unequal normalized sets -> `changed`.

`frameRef` is required and compares by exact reference equality: equal -> `preserved`; unequal -> `changed`.

Particularity anchors compare independently by anchor key across the union of keys declared on either side. Their observations use a stable dimension name such as `particularity:goal:G`.

- same non-null anchor ref -> `preserved`;
- different non-null anchor refs -> `changed`;
- non-null before and absent/null after -> `absent_after`;
- absent/null before and non-null after -> `new_after`;
- explicitly null on both sides -> `indeterminate`.

A key absent from both sides does not enter the comparison because it was not declared by either frame.

The function MUST compare collections deterministically and MUST produce stable observation ordering.

`preserved` is intentionally local and dimension-scoped. It does not imply `same_world`.

## Crossing status

`crossingStatus` is a bounded summary of the tracked observations, not a metaphysical verdict.

- `materially_changed` when one or more tracked dimensions are `changed`, `absent_after`, or `new_after`;
- `indeterminate` when no material change is established but one or more tracked dimensions are `indeterminate`;
- `no_material_difference_observed` only when every emitted tracked observation is deterministically `preserved` and no tracked dimension is indeterminate.

The exact phrase **`same_world` MUST NOT appear as a success state** in v0.1.

`no_material_difference_observed` means only that the bounded declaration did not establish a material difference. It is not proof of global identity.

## Particularity preservation

Particularity anchors defend against a subtle false positive: a route can make something nominally reachable while changing the frame enough that the destination no longer means what it meant before.

Example:

```text
before goal label: "G"
before anchor: goal:G -> artifact-A

after goal label: "G"
after anchor: goal:G -> artifact-B
```

The label survived. The particularity did not.

NAV MUST report this as a changed particularity anchor rather than treating equal labels as continuity.

If a particularity anchor is unavailable on either side, NAV MUST report the deterministic absence/new/indeterminate disposition defined above; it must not infer sameness from surface similarity.

## Authority and influence boundary

A changed authority set is a first-class NAV difference.

The presence of a residue, refusal witness, remembered instruction, retrieved artifact, or visible door may influence later attention or traversal. NAV MUST NOT convert that influence into authority.

A crossing receipt may therefore report both:

```text
residue: preserved
influence source: present
authority: changed
```

without contradiction.

The module does not itself evaluate or grant authority. Where authority validity matters, callers must use the existing Project 0 authority evaluator and pass the resulting attributable references into the frame declaration.

## Refusal boundary

NAV v0.1 may compare frames surrounding a refused crossing, but it does not transform refusal into impossibility everywhere.

A refusal remains frame-relative evidence:

```text
attempt A -> X
under declared frame F / constitution C
result: refused with attributable reason codes
```

NAV may preserve that boundary witness as crossing evidence. It MUST NOT conclude that `X` is impossible in every frame, nor propose a different frame that would permit it.

## Addressing and receipt boundary

`FrameSnapshot`, `CrossingDeclaration`, and `NavCrossingReceipt` are experimental NAV records. `NavCrossingReceipt` is not a new canonical Floor 1.1 `ReceiptType`.

The implementation MUST reuse Project 0’s existing canonicalization and SHA-256 machinery. It may define one explicit experimental NAV domain prefix and address each NAV record through an envelope such as:

```ts
{
  recordType: "frame_snapshot" | "crossing_declaration" | "crossing_receipt",
  body: record
}
```

using the existing `canonicalizeDomainValue(...)` helper.

This yields deterministic `NavRecordRef` values for the exact before snapshot, crossing declaration, and after snapshot cited by the crossing receipt. The implementation may use the resulting SHA-256 digest representation as the experimental ref; it MUST NOT masquerade as a canonical Node, Edge, Receipt, or Request address.

The implementation MUST NOT:

- emit a `rect-...` canonical receipt identity unless Project 0 later explicitly versions NAV into the canonical receipt contract;
- silently add `NavCrossingReceipt` to `RECEIPT_TYPES`;
- change canonical Node, Edge, Receipt, or Request bytes or addresses;
- implement another JCS encoder, canonical serializer, or digest algorithm.

This keeps v0.1 additive, replay-addressable, and experimental.

## Determinism

Given structurally equivalent inputs, NAV MUST produce byte-for-byte equivalent canonical NAV bodies and identical NAV digests.

Determinism includes:

- stable set normalization;
- stable particularity-key ordering;
- stable observation ordering;
- explicit null/missing handling;
- no wall-clock reads inside comparison;
- no random identifiers;
- no model inference;
- no environment-dependent lookup.

The crossing receipt’s three input refs MUST resolve to the exact addressed declarations used to calculate it in any in-memory test store or fixture that supports resolution.

## Error handling

Malformed input must fail before comparison with stable NAV-specific validation reason codes or typed errors.

Logical uncertainty must remain distinct from malformed input:

- malformed structure -> validation failure;
- valid but insufficient declaration -> `indeterminate` observation/status;
- valid material difference -> `materially_changed`;
- fully comparable declared preservation -> `no_material_difference_observed`.

No error path may mutate inputs or existing Project 0 history.

## Initial adversarial fixtures

### 1. Same wording, changed authority and decoder

Before and after contain an identically worded goal and the same visible artifact reference. Authority and decoder references change during the crossing.

Expected:

- artifact/evidence may be `preserved`;
- authority is `changed`;
- decoder is `changed`;
- crossing status is `materially_changed`;
- no `same_world` claim exists.

### 2. Particularity drift under stable label

Before and after both name goal `G`, but `goal:G` points to different particularity anchors.

Expected: particularity is `changed` even though the label is identical.

### 3. Missing decoder evidence

Before declares a non-null decoder; after declares `decoderRef: null`.

Expected: decoder is `absent_after`, and crossing status is `materially_changed`.

If both sides declare `decoderRef: null`, decoder is `indeterminate`, not preserved.

### 4. Influence without authority

A refusal residue remains visible after crossing, but the authority set does not contain any grant derived from that residue.

Expected: residue/evidence visibility may be preserved while authority remains independently preserved or changed according to its own declared refs. No authority is synthesized from influence.

### 5. Reordered equivalent sets

Equivalent authority/evidence sets arrive in different array orders.

Expected: stable normalized comparison and identical NAV digest.

### 6. Identical bounded frames

All declared tracked dimensions are deterministically preserved.

Expected: `no_material_difference_observed`, never `same_world`.

### 7. Refusal remains frame-relative

Crossing evidence contains a stable refusal reason code under frame F.

Expected: NAV records the refusal evidence but makes no claim that the destination is impossible under other frames and emits no route recommendation.

### 8. Replay-addressable inputs

The same crossing receipt is recalculated from addressed before/crossing/after records loaded in a different insertion order.

Expected: the three input refs resolve to the same exact declarations and the receipt body/digest are identical.

## Acceptance criteria

The first implementation is complete when:

1. `src/nav-crossing/` contains pure types, validation, comparison, and addressing functions only.
2. Existing canonical addressing is reused; no second canonicalizer or hash implementation appears.
3. No canonical node kind, relationship kind, or Floor 1.1 receipt type is added.
4. Comparison distinguishes `preserved`, `changed`, `absent_after`, `new_after`, and `indeterminate` using the rules in this spec.
5. Any changed, removed, or newly introduced tracked dimension forces `materially_changed`.
6. Missing tracked comparison evidence cannot silently produce preservation.
7. Surface equality cannot override changed particularity anchors.
8. NAV never emits a `same_world` verdict.
9. NAV never proposes a route, alternate authority, alternate evidence, alternate decoder, or minimum world-change.
10. Equivalent inputs with reordered sets produce the same result and digest.
11. The crossing receipt cites replay-addressable refs for the exact before snapshot, crossing declaration, and after snapshot used to calculate it.
12. Inputs are not mutated.
13. Focused NAV tests pass and the repository’s existing verification gate remains green.

## Compatibility and migration

This design is additive.

It does not change existing canonical identities, ontology kinds, relationship types, Floor 1.1 receipt types, authority semantics, or Witness residue behavior.

Downstream consumers may choose to adopt experimental NAV records. They must not treat experimental NAV digest identity as canonical Project 0 Receipt identity.

If NAV later graduates into the canonical receipt contract, that requires an explicit versioned design, compatibility statement, fixtures, and migration boundary. v0.1 does not pre-authorize that graduation.

## Relationship to neighboring primitives

### Field Traversal & Illumination

That pattern distinguishes threshold probing from deliberate traversal. NAV v0.1 supplies the next cold question: after a crossing is declared, what locally changed?

### Refusal Topology

Refusal Topology preserves accountable negative-space witnesses. NAV may carry those witnesses as crossing evidence without upgrading them into universal law.

### Lawful Reachability / Constituted Reality

Lawful Reachability asks what state counts as constituted from accountable history. NAV asks what changed between two declared local frames. Neither replaces the other.

### Minimum necessary world-change

Deferred. A future NAV route-planning slice may ask what smallest legitimate frame transformation could make a refused goal reachable while preserving particularity. That future primitive must consume v0.1 distinctions rather than collapse them.

## Design sentence

> NAV v0.1 is a deterministic crossing witness: it preserves enough local difference to prevent the navigator from saying “same” when the declared world has quietly become different.
